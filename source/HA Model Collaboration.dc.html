How to use this manual
  1. Read the principles in section 1 — they are the ideas everything else rests on.
  2. Find your role in section 2 so you know what you are responsible for.
  3. Follow the weekly cycle in section 5 — this is the core routine.
  4. Keep the pre-publish checklist in section 8 somewhere visible.
01 — Purpose & Coordination Principles

This manual explains how we author, exchange, and coordinate BIM models across every discipline. It exists so that architects, engineers, and the wider design team all work to one shared rhythm and one source of truth.

Follow it and coordination stays predictable: fewer clashes, less rework, and no unpleasant surprises before a deadline.

Four non-negotiable principles

Single source of truth

All models live in the Common Data Environment (CDE). Never email models around or keep private copies to share.

Coordinate early & often

We federate weekly, not at the end of a stage. A steadily falling clash count beats a last-minute scramble.

Publish only what is checked

A broken model harms everyone downstream. You are the gatekeeper for your own model.

One rhythm

The weekly publish cutoff is fixed. We work to the rhythm; the rhythm does not wait for anyone.

02 — Roles & Responsibilities

Clear ownership matters more than any tool.

Role
Responsible for
BIM Manager
Owns this manual and the BIM Execution Plan, the CDE structure, and the modelling and naming standards — and makes sure they are followed.
BIM Managers / Coordinator
Combines (federates) the models each week, runs clash detection, keeps the issue register, and chairs the coordination meeting.
BIM Leads - Associates / Architects 
Accountable for their model's health, publishing on time, and closing the issues assigned to them.
Design Leads - Associates Directors
Make the design decisions when a clash needs a genuine design change rather than a modelling fix.
Authors- Architects
Produce and maintain the model content to the agreed standard and level of detail.
03 — Where Models Live: the CDE

The Common Data Environment - Autodesk Forma is the single online home for every model and drawing. Each model moves through four states so everyone always knows what is trustworthy.

Work in Progress

Your team's live working model, still being developed.

Shared

A checked model published for coordination.

Published

Authorised and formally issued information.

Archived

Superseded versions kept for the record.

Everyone uses the same platform, and it is the only route for exchanging models — no side channels.

04 — Setting Up Your Model

Get these right at the start or coordination will fight you every week.

1
Shared coordinates. Everyone uses the agreed project origin, base point, and true north. Mismatched coordinates are the single biggest cause of federation problems.
2
Consistent units across all authoring tools.
3
Model splitting. One model per discipline; on large projects, also split by zone or level to keep files fast.
4
Naming. Follow the naming convention for every file, so models are easy to find and versions never get confused.
5
Level of information need. Model to the agreed level of detail for the current design stage — no more, no less.

06 — Clash Detection & Issues
Clash matrix

We only test the discipline combinations that matter — e.g. structure against building services — so we are not buried in irrelevant clashes.

Tolerances

Hard clashes (physical overlap) and clearance clashes (not enough access space) each have agreed thresholds to filter out noise.

Priorities

We fix design-significant clashes first, not tiny modelling noise.

Issue format

Issues travel as BCF, so teams on different software can send and receive them. Every issue sits in one register with an owner, status, and due date.

08 — Before You Publish: the Checklist

Run through this every time before moving your model to Shared.

Model purged and cleaned — no critical warnings or errors.
Correct shared coordinates, origin, and units.
Named per the agreed convention.
Modelled to the agreed level of detail for this stage.
Native and IFC exported with the agreed settings.
Uploaded to Shared before the cutoff time.
09 — Glossary
Term
Meaning
BIM
Building Information Modelling.
CDE
Common Data Environment — the single online home for all models and information.
WIP / Shared / Published / Archived
The states a model moves through in the CDE.
Federated model
All discipline models combined into one coordinated view.
Clash detection
Automatically finding where elements overlap or lack clearance.
Clash matrix
The grid defining which disciplines are checked against which.
BCF
BIM Collaboration Format — an open way to exchange coordination issues between different software.
IFC
Industry Foundation Classes — a neutral, tool-independent model format.
LOIN / LOD
Level of Information Need / Level of Detail — how much detail a model carries at each stage.
Origin / base point
The agreed reference point that keeps all models aligned.
